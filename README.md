# imcp-parser

Извлечение данных обоснования НМЦД из Excel-файлов произвольной структуры:
коммерческие предложения поставщиков, расчёт начальной максимальной цены
договора, сметы на работы и услуги.

Зависит только от `openpyxl` и `pydantic`.

## Задача

Обоснование НМЦД приходит в Excel, и единого формата у этих файлов нет.
Меняется всё: число листов и их названия, порядок и формулировки
заголовков, количество строк шапки, число организаций в блоке цен,
присутствие необязательных колонок. Разметка «по адресам ячеек» на таких
данных не работает — файл с той же логикой, но смещённой на две строки
таблицей, ломает парсер.

Библиотека распознаёт структуру листа по смыслу заголовков, а не по
координатам: находит шапку, определяет тип листа, вычисляет колонки по
якорям и только потом читает данные.


### Якоря вместо адресов ячеек

Заголовок ищется по нормализованному тексту с учётом словоформ: якорь
`"наименова товар"` найдёт и «Наименование товара», и «Наименования
товаров». Нормализация снимает регистр, лишние пробелы, пунктуацию и
`ё`/`е`.

Якоря комбинируются, что позволяет описать неоднозначные заголовки:

```python
_ITEM_IMCP_ANCHORS = AllOfAnchors(
    AnyOfAnchors(MatchAnchor("нмц товар"), MatchAnchor("нмц средн арифм")),
    NotContainsAnchor("един"),
)
```

Здесь `NotContainsAnchor` отсекает «НМЦ единицы товара» — колонку с другим
смыслом, заголовок которой иначе совпал бы с искомым.

### Самоопределение листов

Лист сам отвечает, его ли это файл. `BaseSheet` ведёт реестр подклассов
через `__init_subclass__`, экстрактор перебирает реестр и отдаёт лист
первому классу, который себя признал:

```python
class GoodsSheet(BaseSheet[GoodsSheetParseResult]):
    @classmethod
    def is_me(cls, ws: Worksheet) -> bool:
        sheet = cls(ws)
        if sheet._has_title_anchors(_GOODS_SHEET_TITLE_ANCHOR):
            return True
        return sheet._has_table_header((_ITEM_IMCP_ANCHORS, _ITEM_NAME_HEADER_ANCHOR))
```

Распознавание двухступенчатое: сначала по названию листа, затем по набору
заголовков — название часто бывает неинформативным («Лист1»). Новый тип
листа добавляется одним классом, без правок экстрактора.

### Блок цен переменной ширины

На листе товаров цены лежат матрицей: строки — позиции, колонки —
организации, и число организаций меняется от файла к файлу. Границы блока
определяются по родительскому заголовку «Цена единицы товара», организации
читаются из строки под ним, а позиции и цены извлекаются согласованно,
чтобы не потерять связь «позиция — организация — цена».

### Разбор значений

Числа в таких файлах приходят строками с пробелами-разделителями разрядов,
запятой вместо точки и символом валюты. Суммы разбираются в `Decimal`, без
`float`. Ставка НДС и признак «в том числе / кроме того» вычитываются из
текста заголовков и строк — отдельной колонки для них обычно нет.

## Пример

```python
from imcp_parser import OpenpyxlExcelIMCPExtractor

extractor = OpenpyxlExcelIMCPExtractor()
result = extractor.extract_imcp(content=xlsx_bytes)

print(result.goods_imcp_avg)
for org in result.goods_data.organizations:
    print(org.id, org.name)
```

Если ни один лист не распознан, поднимается `IMCPNotFoundError` — вызывающий
код отличает «это не обоснование НМЦД» от «данные не извлеклись».

Готовый к запуску пример — `examples/parse_goods_sheet.py`: собирает товарный
лист в памяти и печатает разобранный результат.

```bash
python examples/parse_goods_sheet.py
```

## Происхождение кода

Модуль выделен из закрытого проекта автоматизации проверки закупочной
документации, с разрешения правообладателя. Перенесена история коммитов
только относящихся к нему файлов, поэтому в `git log` есть коммиты других
участников команды. Их коммиты сохранены, но имена и адреса заменены на
`Contributor B`, чтобы не публиковать персональные данные без согласия.

Около 97% строк в текущем срезе — мои: механизм якорей, базовый лист с
поиском шапки и реестром типов, парсеры листов товаров и работ, разбор
чисел и НДС, сборка результата и все тесты. Чужое — правки типизации и
переименования файлов.

История сохранена подробно: 69 моих коммитов показывают, как парсер
развивался — от базовых абстракций якорей и колонок к самоопределяющимся
листам, реестру типов и согласованному извлечению блока цен.

При выделении удалён слой интеграции с исходным приложением (pipeline,
хранилище документов, слияние полей из нескольких документов), данные в
тестах заменены синтетическими.

## Условия использования

Репозиторий опубликован как демонстрация инженерных решений, а не как
библиотека для повторного использования. Файл лицензии отсутствует:
исключительные права на исходный проект принадлежат заказчику, часть строк
написана другими участниками команды. Разрешение на копирование, изменение
и распространение не предоставляется.
